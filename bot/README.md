# АвоПеренос (`@avoperenos_bot`)

Telegram-бот для учёта переносов, замен и задач кураторов онлайн-школы.

**Готовы этапы 1–8** (бот можно держать постоянно на сервере).

- **Этап 1:** установка на Windows, база сотрудников, вход по Telegram ID, меню по ролям, управление сотрудниками для администратора.
- **Этап 2:** разовые и постоянные переносы — создание (пошаговая форма с превью), статусы и комментарии, карточка заявки, «Активные заявки» / «Мои заявки» / «На контроле» / поиск.
- **Этап 3:** массовый перенос — общая заявка (преподаватель, причина, период), ученики с подзадачами и независимыми статусами, прогресс.
- **Этап 4:** подбор замены — увольнение / временное отсутствие, этапы по ученикам, история кандидатов, помощь старшему.
- **Этап 5:** график кураторов 2/2 (Ксения / Юлия от 14.11.2026), календарь, разовые подмены, назначение заявок на дежурного.
- **Этап 6:** смена дежурства в 08:00, напоминания в рабочих часах, срочность, APScheduler.
- **Этап 7:** статистика для админа, предупреждения стабильности (30 дней), еженедельный отчёт, CSV.
- **Этап 8:** финальная проверка, Docker, постоянный хостинг (Timeweb Cloud / Beget).

**Постоянный сервер (рекомендуется):** пошаговая инструкция → [`docs/hosting-timeweb.md`](../docs/hosting-timeweb.md)  
(Timeweb Cloud — самый дешёвый VPS; кратко — Beget как альтернатива. Токен только в `.env`, не в чаты.)

## Установка (один раз)

1. Откройте папку проекта `bot` (эта папка с `START_BOT.bat`).
2. Дважды щёлкните **`setup_windows.bat`**.
3. Скрипт создаст окружение `.venv`, поставит библиотеки, скопирует `.env.example` → `.env` и создаст базу.  
   Текст сообщений в `.bat` на английском — из‑за кодировки Windows `cmd` (кириллица в `echo` ломается).
4. Откройте файл **`.env`** в Блокноте или Cursor и заполните:

```env
BOT_TOKEN=сюда_вставьте_токен_от_BotFather
ADMIN_TELEGRAM_ID=сюда_ваш_числовой_Telegram_ID
DATABASE_URL=sqlite:///./avoperenos.db
TIMEZONE=Europe/Moscow
```

5. Если вы меняли `.env` после первой установки — снова запустите `setup_windows.bat` или выполните инициализацию БД вручную (см. ниже).

## Запуск бота (Windows)

1. Дважды щёлкните **`START_BOT.bat`**.
2. Окно должно оставаться открытым — бот работает, пока окно открыто.
3. В Telegram откройте **`@avoperenos_bot`** и отправьте команду **`/start`**.
4. Вы должны увидеть приветствие с авокадо 🥑 и меню под вашей ролью.

### Остановка

В окне `START_BOT.bat` нажмите **Ctrl+C**, затем Enter при запросе. Или просто закройте окно.

### Как обновить Windows-версию

1. **Не удаляйте** файлы `.env` и `avoperenos.db` — в них токен, ваш ID и все заявки.
2. Скопируйте новые файлы проекта поверх старых (или распакуйте архив в ту же папку, согласившись на замену).
3. Если изменился список библиотек — снова запустите **`setup_windows.bat`**.  
   Скрипт **не перезапишет** уже существующий `.env`.
4. Запустите **`START_BOT.bat`** и проверьте `/start` в Telegram.

Для работы 24/7 без включённого ПК используйте сервер: [`docs/hosting-timeweb.md`](../docs/hosting-timeweb.md).

## Кто что видит

| Роль | Меню |
|------|--------|
| **Куратор** | Добавить перенос, Массовый перенос, Подбор замены, Активные заявки, На контроле, График кураторов, Поиск заявки |
| **Старший преподаватель** | Создать заявку, Мои заявки, Подбор замены, Найти заявку |
| **Администратор** | Все пункты куратора и старшего + **График дежурного**, **Управление сотрудниками**, **Настройки**, **Статистика** |

Неавторизованный пользователь получает отказ **без** показа чужих данных.

### Заявки (этапы 2–4)

- **Добавить перенос** / **Создать заявку** — разовый или постоянный, форма с «Назад» / «Отмена», превью и подтверждение.
- **Массовый перенос** — общая заявка + подзадачи по ученикам (действие: предложить перенос / согласовать отмену / временная замена / уточнить у родителя). Общая заявка открыта, пока не закрыты все подзадачи; на карточке виден прогресс.
- **Подбор замены** — увольнение или временное отсутствие: ФИО преподавателя, даты, ученики (предмет + расписание). По каждому ученику этапы: ищем → найден (ФИО) → предложили родителю → согласовано; кнопки «искать другого» (история кандидатов), «нужна помощь старшего», «ученик не продолжает» (с причиной).
- Статусы переносов: ещё не написали → ждём ответа → выполнено / отказ. «Выполнено» только вручную (на подзадаче — независимо).
- Поиск и списки находят массовые заявки и заявки на замену (в т.ч. по ученику из подзадач).
- Ответственный: создатель-куратор или админ — себе; иначе дежурный по графику 2/2 на «сегодня» школы (`TIMEZONE` из настроек).

### График кураторов (этап 5)

- Цикл **2/2**: Ксения (14–15.11.2026) → Юлия (16–17) → Ксения (18–19) и далее непрерывно (месяц/год не сбрасывают фазу).
- **График кураторов** — месячный календарь, часовой пояс и рабочие часы 08:00–21:00 из настроек школы.
- **График дежурного** (админ; также «Управление графиком»): стартовый экран с текущим циклом и действиями — назначить дежурного на день, поменять два дня (с подтверждением), задать цикл 2/2 с даты (с подтверждением), календарь. Разовые подмены (*) не ломают общий цикл; «Убрать подмену» возвращает день к циклу.
- Добавьте в сотрудники кураторов с именами **Ксения** и **Юлия** — стартовый цикл создастся сам.

### Автоматизация (этап 6)

- **08:00** (часовой пояс школы): если дежурный сменился — незакрытые заявки переходят новому; статусы и история сохраняются. Сообщение дежурному: доброе утро, счётчики (срочные / ждём / не обработано) и кнопка «Открыть задачи».
- Если куратор тот же — задачи остаются. Ручная подмена дежурного на «сегодня» — переназначение сразу.
- **20:45** — сводка незавершённых; после **21:00** обычные напоминания уходят на следующий рабочий день (остаток интервала сохраняется).
- Напоминания: после «написали ученику» — через 2 раб.часа, далее каждые 3; замены: ищем / найден / ждём — свои интервалы. Интервалы и ID рабочего чата правятся в **Настройки**.
- Срочность: перенос <3 ч до занятия; замена <24 ч до ближайшего и не согласована → ЛС дежурному + рабочий чат (антиспам).
- Планировщик APScheduler с jobstore в SQLite — переживает рестарт, без дублей job id; после выполнено/отказ напоминания снимаются.

### Статистика (этап 7, админ)

- Меню **Статистика**: по преподавателям и по ученикам; периоды 7 / 30 дней, календарный месяц, произвольный.
- По преподавателю: случаи переноса vs затронутые занятия (массовая = 1 случай отсутствия, N занятий), уникальные ученики, инициаторы, статусы, история. Родитель / школа не считаются нарушением стабильности.
- По ученикам: переносы за период, преподаватели-инициаторы, даты, согласовано/открыто; сортировка по количеству. В текстах бота показываем ФИО, без акцента на ID ученика.
- Предупреждения: 2+ переноса за скользящие 30 дней по инициативе преподавателя — куратору при создании; 3+ — куратору и админу. Не блокирует создание; без спама при повторном открытии; массовые — по каждому ученику; отказы, дубли, родитель и школа не учитываются.
- По понедельникам 09:00 — еженедельный отчёт админу + кнопка подробной статистики; выгрузка CSV (Excel).

### Управление сотрудниками (админ)

В меню: **Управление сотрудниками** → добавить по Telegram ID + имя + роль, список, деактивация доступа.  
Первый администратор создаётся автоматически из `ADMIN_TELEGRAM_ID` при старте / `setup_windows.bat`.

## Типичные ошибки

| Проблема | Что сделать |
|----------|-------------|
| `Python не найден` | Переустановите Python 3.12 с галочкой PATH, откройте новое окно командной строки |
| `BOT_TOKEN не задан` / похож на заглушку | Заполните настоящий токен в `.env` |
| `ADMIN_TELEGRAM_ID` | Укажите своё число (не username) |
| После `/start` «Доступ запрещён» | Ваш ID должен совпадать с `ADMIN_TELEGRAM_ID` или вас должен добавить админ |
| Окно сразу закрывается | Запускайте через `START_BOT.bat` — в конце будет `pause` при ошибке |
| Антивирус блокирует `.bat` | Разрешите скрипт или запускайте команды из таблицы выше вручную |

## Структура проекта (кратко)

- `bot/` — код бота (config, db, handlers, middlewares, services)
- `scripts/init_db.py` — создание таблиц и первого админа
- `tests/` — автотесты
- `alembic/` — миграции БД (этапы 1–6; этап 7 без новой схемы)
- `Dockerfile`, `docker-compose.yml` — постоянный сервер (`docker compose up -d`)
- `data/` — база SQLite на сервере (том Docker; не удаляйте при обновлении)

## Docker (сервер)

Кратко (полная инструкция: [`docs/hosting-timeweb.md`](../docs/hosting-timeweb.md)):

```bash
cp .env.example .env   # заполнить BOT_TOKEN и ADMIN_TELEGRAM_ID
mkdir -p data
docker compose up -d --build
docker compose logs --tail 50
```

База пишется в `./data/avoperenos.db`. При блокировке Telegram API задайте `TELEGRAM_PROXY` в `.env`.
